# M4 — Reference-system evaluation

[Start here](../START_HERE.md)

## Independent assignment

Use `evaluate.py` to compare the nominal and calibrated controllers on the same reference system. Use the policies trained in M3 to make a reproducible comparison, save the measured results, and explain them. The existing evaluation code is a completed reference; implement your own attempt in your project copy. Choose your own code organization; ask for hints or review as needed.

The reference system is the software stand-in in `real_robot.py`, not physical hardware. Use only its public `run_policy_on_real` function, without reading its hidden parameters. No new network, training objective, or parameter search is required for this milestone.

## First task

Inspect your existing evaluation loop. Decide where to set matching evaluation conditions, where to keep the full error tensor, and how to retain both scalar results for saving.

## Requirements

1. Keep the two-policy comparison. Use matching training settings and seeds; only the simulator's L and b should differ between training runs.
2. Evaluate both on the same reference system with the same target and evaluation settings. Set the same explicit PyTorch evaluation seed immediately before each reference-system call so any random conditions driven by PyTorch are matched. Record that seed separately from the training seed. Use evaluation mode and disable gradient tracking for these calls; never update policy weights during evaluation.
3. Retain each returned error tensor long enough to inspect its shape. Confirm it has shape `(n, T)`, contains finite, nonnegative absolute angle errors, and has at least 100 time steps.
4. For each controller, report the mean error across all trajectories and the last 100 time steps, in radians. This is a late-window estimate of holding error, not proof of an exact steady state.
5. Save both results to `results/m4_comparison.csv` or JSON. Include controller name, simulator L and b used for training, measured error, seeds, training iterations and learning rate, and the observed evaluation shape. Retain enough precision to reproduce your comparison.
6. Report absolute error reduction and relative reduction: `100 * (nominal_error - calibrated_error) / nominal_error`. If nominal error is zero, report percentage reduction as undefined. Negative reduction means calibration performed worse; report it honestly.
7. In your personal notes, record the values and explain in 3–4 sentences why calibration could help transfer, whether this run supports that hypothesis, and what one run cannot establish.

Useful tools: `policy.eval()`, `torch.no_grad()`, `torch.manual_seed`, `.shape`, `torch.isfinite`, slicing, `.mean()`, `.item()`, and Python's `csv` or `json` module. These are references, not a prescribed implementation sequence.

## Existing evidence and completion check

A previously reviewed run measured approximately **0.0367 rad nominal** and **0.0043 rad calibrated**, around **88% lower error**. Use your newly saved measurements as the final record; these earlier values are context, not answers to hard-code.

Finish when `python evaluate.py` runs, both results are finite and evaluated under matching conditions, the result file matches the printed metrics, and your explanation distinguishes training cost from reference-system performance. Keep the existing M3 training plot; it does not substitute for this evaluation comparison. No additional plot is required for M4.

Running evaluate.py currently repeats calibration and both training runs. You do not need to run every Python file separately. A successful comparison need not always show improvement; do not tune on the reference results to force the expected outcome.
