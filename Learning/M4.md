# M4 — Reference evaluation

[Start here](../START_HERE.md) · [Project results](../README.md)

**Goal:** compare nominal and calibrated controllers fairly in `evaluate.py`. Use only the public `run_policy_on_real` function; the reference system is software.

## Assignment

1. Keep training settings and seeds equal; only training-simulator L and b should differ.
2. Evaluate with matching target and call settings. Set the same PyTorch evaluation seed before each call, separately from the training seed. Use `policy.eval()` and `torch.no_grad()`; do not update weights.
3. Inspect each returned error tensor: shape **(n, T)**, `n > 0`, `T ≥ 100`, finite and nonnegative. Entries are absolute angle errors in radians.
4. Compute `errors[:, -100:].mean().item()` for each controller. This measures late holding performance, not early motion.
5. Save both rows to `results/m4_comparison.csv`: controller, L, b, error, training/evaluation seeds, training iterations, learning rate, and evaluation shape.
6. Report reductions:

```text
absolute = nominal error − calibrated error
relative = absolute / nominal error × 100
```

If nominal error is zero, percentage reduction is undefined. Negative reduction means the calibrated controller performed worse.

## Finish when

- `python evaluate.py` runs and saved values match printed metrics.
- You can explain why calibration may help and what this run actually shows.
- Your own README includes a comparison table, one labeled plot, commands, and a short conclusion. Distinguish training cost from reference error; mention limits of one setup and a software reference.

The recorded project achieved about **88.34%** lower error. Use your measured values; do not tune the comparison to force improvement. One average can hide transient errors or poor individual trajectories.

`evaluate.py` repeats calibration and training; you do not need to run every file separately. Keep the M3 plot and record your findings. This completes **M0–M4**.
