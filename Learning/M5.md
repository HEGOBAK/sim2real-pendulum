## Independent assignment — about 20–30 minutes

Turn README.md into a short, reproducible report of the experiment you completed. Your end product is a GitHub visitor being able to understand the question, inspect the evidence, and rerun the comparison. Choose your own wording and layout. No new model or experiments are required.

## Start here

Open `results/m4_comparison.csv` and the Results section in `README.md`. Fill the comparison table from that CSV, including each controller's training L and b and its measured mean absolute angle error. Label the error as **mean over the last 100 steps on the software reference system (rad)**. Round for readability; preserve the full-precision CSV.

## Requirements

1. Explain the experiment in your own words: reference motion data → fit simulator L and b → train nominal and calibrated controllers → compare both on the same reference system. Distinguish the parameters learned in calibration from those learned during controller training.
2. Complete the results table and report absolute reduction in radians and relative reduction in percent. Link the saved CSV. Use the verified measurements, not expected outcomes.
3. Embed one existing plot with a short caption. Choose `figures/m2_calibration_loss.png` or `figures/m3_training_comparison.png`; explain what it measures. Training cost alone does not prove better reference-system performance—the comparison table supplies that evidence.
4. Add reproducible commands from the project root: create/activate a Python virtual environment, install `requirements.txt`, run the simulator tests, then run `evaluate.py`. Explain that evaluation repeats calibration and both training runs, and identify where it saves its outputs. Record training seed, evaluation seed, iterations, and learning rate from the CSV. If your chosen figure comes from `calibrate.py`, include that command too.
5. Write 3–4 sentences interpreting the improvement and its limits. The reference is software, not physical hardware; one training seed and one evaluation setup do not establish reliability across all conditions. The final-window average can hide transient or individual-trajectory failures.
6. Update the milestone checklist to reflect completed work. Remove stale starter instructions or machine-specific assumptions that would confuse another reader. Add a brief personal takeaway in WORKLOG.md; preserve your earlier notes.

Useful Markdown syntax: `[label](relative/path)` for links, `![caption](figures/filename.png)` for images, triple backticks for command blocks, and `|` separators for tables. Use repository-relative paths in README so links work on GitHub.

## Completion check

- Numbers agree with the CSV, and units and averaging window are explicit.
- The plot renders, and its caption distinguishes training evidence from evaluation evidence.
- Commands match the actual project and identify generated outputs.
- Conclusions distinguish measured findings from what remains untested.
- README, WORKLOG, and linked artifacts are committed and pushed after review.
