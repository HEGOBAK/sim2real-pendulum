# Writing preferences

- Keep README and guides simple, short, and efficient.
- Use direct wording, short paragraphs, and concrete examples. Avoid long introductions, repeated explanations, and decorative language.
- Preserve essential commands, shapes, requirements, results, and completion checks. Shorter must still be usable by a beginner.
- Keep the learning path README → START_HERE → M0 → M1 → M2 → M3 → M4, with one start page.
- WORKLOG.md is exempt from this style rule. Preserve the author's wording and organization unless explicitly asked to edit it.
- Documentation requests do not authorize code changes.
